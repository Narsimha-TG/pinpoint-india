# Pinpoint India

A Next.js App Router starter for an India pincode and nearby-places directory. It includes server-rendered state, city and pincode routes; per-location metadata and JSON-LD; generated sitemap and robots endpoints; a server-side Google Places proxy; a responsive local guide UI with optional Google Maps; a context-aware chatbot that answers from the displayed postal record and points users to nearby-place filters; and a WhatsApp share action that prepares the locality, pincode, map link (when coordinates are available), and guide URL. The chatbot is a deterministic helper, not a generative AI service.

> **Coverage note:** this workspace starts with one clearly marked sample entry (Hyderabad GPO, 500001). It is not a complete India postal directory and does not guarantee search rankings. Pincode records are looked up through the public India Post Pincode API when not present in the local sample list; confirm official details with India Post. Expand `lib/locations.ts` with a licensed, verified India Post dataset before launching broad programmatic pages. Only publish pages with useful, accurate content.

## Requirements

- Node.js 20.9 or later
- npm
- Optional Google Maps Platform project with Places API (New), Geocoding API and Maps JavaScript API enabled and billing configured

## Setup

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env.local`.
3. Set `NEXT_PUBLIC_SITE_URL` to the canonical production origin before deployment.
4. For nearby places, set `GOOGLE_MAPS_API_KEY` to a server-only key with Places API (New) and Geocoding API enabled. Restrict the key appropriately. It is never sent to the browser.
5. To show interactive maps, set `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` to a separate browser key with Maps JavaScript API enabled and HTTP-referrer restrictions configured. Google Maps Platform usage may incur charges; set quota and billing alerts.
6. Run `npm run dev` and open `http://localhost:3000`.

Without Google keys, the site and SEO routes work, and map/places sections show helpful setup messages. The postal lookup integration is an external service and can be unavailable; the demo record remains available without it.

## Routes and features

- `/india` — available states
- `/india/[state]` — state directory
- `/india/[state]/[city]` — city/district directory
- `/india/[state]/[city]/[pincode]` — postal guide, metadata, canonical URL, Place + PostalAddress, BreadcrumbList and FAQPage JSON-LD
- `/api/places` — POST proxy for Google Places Text Search; validates inputs and keeps the server key private
- Pincode guide chatbot — answers basic questions from the current location record, with a reminder to verify official details
- WhatsApp sharing — opens WhatsApp with location and guide details prefilled; the user reviews and sends the message
- `/sitemap.xml` and `/robots.txt` — generated by Next.js

The sitemap lists currently known local records; it cannot enumerate every possible postal API record. Import an authoritative dataset and update `lib/locations.ts` plus `app/sitemap.ts` for full-catalog coverage. Keep schema claims consistent with visible page content and Google's current structured-data policies; FAQ rich-result display and search ranking are not guaranteed.

## Deployment

Deploy to a Node-compatible Next.js host. Configure the environment variables in the hosting dashboard, use separate restricted Google API keys for server and browser use, and set `NEXT_PUBLIC_SITE_URL` to the canonical HTTPS origin. Verify sitemap URLs, API quotas, postal data licensing, privacy disclosures and structured data before indexing.
